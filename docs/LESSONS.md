# 教训

这些每一条都花掉过真实时间，而且没有一条是读代码能看出来的。

按「犯错的代价」从大到小排。后面几条是好奇心那一层的，单独一组。

---

## 一、没在清单里声明的配置键或工具，会让插件整个不加载

`openclaw.plugin.json` 带 `additionalProperties: false`。`config` 里任何一个
没在 `configSchema.properties` 声明的键，会让插件整个拒绝加载，gateway 每
20 秒重试一次，日志里只有这一句：

```
invalid config
```

工具同理：实现了但没写进 `contracts.tools`，就永远不会注册，而且没有任何
提示。

**能跑通的顺序：** 清单 → 代码 → `openclaw.json` → `openclaw config validate`
→ 重启。

**提交前自动核对：**

```bash
# 每个声明的工具都必须真的存在
python3 -c "
import json,re
j=json.load(open('openclaw.plugin.json'))
src=open('index.js').read()
declared=set(j['contracts']['tools'])
impl=set(re.findall(r'name:\s*[\"\']([a-z][a-z0-9_]+)[\"\']', src))
print('缺失:', declared-impl)
"
```

## 二、游标写的字段名和读的对不上，会静默重放

```js
// 写入
const next = { day: fresh.day, end: fresh.end };
// 读取
const offset = cursor.offset ?? 0;
```

游标文件永远停在 `{"day":"...","offset":0}`。每次唤醒都重读整篇日记，把同样
的行重复入库，经历池被同一个下午灌满。

**没有报错。** 文件存在、能解析、看起来很合理。两半各用一个单独看都说得通
的名字。

**规则：** 游标是一对（名字，含义），由两个模块共享。要测的是「文件内容等于
读取方期待的值」，不是「写入方跑过了」。

## 三、空匹配器会被算成「最新奇」

```js
idle: { verbs: [] }      // 没有模式
```

`classify()` 拿日记行去匹配 `verbs`。空数组匹配不到任何东西，`exposure` 永远
是 0。0 次接触被读成 `unexplored`，而 `unexplored` 的新奇度是 1.0 —— 最高分。

**十二类活动里最不活跃的那一个，成了每天每次唤醒的第一推荐，持续了一整天。**

系统反复告诉她「你从来没试过什么都不干」，她什么都不干了，回了 NO_REPLY，
留不下任何痕迹，于是下次还是同一条建议。**这个推荐绕过了自己的度量。**

**规则：** 没有模式的检测通道，和一个完美的「不存在」无法区分。在相信计数器
之前，先确认真实数据上每个分类器至少能命中一次。

另外：**无法被观测为完成的提议，不该被提议。**「什么都不干是正当结果」属于
提示词里的许可，不属于调度器里的候选。

## 四、两个写入者共用文件，丢的是字段不是文件

`scan()` 从日记重建所有计数器，每个类型都从 `emptyStat()` 起算。`note()` 往
同一个文件写失败数。谁后跑谁赢。

日记是「发生过什么」的真实来源，它永远不含「试过但没成」。所以「从源头重建」
对一部分字段是对的，对另一部分是破坏性的。

**规则：** 逐个字段点名它的权威写入者。重建函数必须把源头无法重现的字段带
过去。

## 五、移植算法要抄原文，不能凭记忆

从一个参考实现移植好奇心引擎，三处出错，每一处在移植版里都看不出来，在原文
里都一目了然：

| | 原文 | 移植版 |
|---|---|---|
| 接触项 | `exposureCount / maxExposure`（正比） | 反了过来，当稀缺度用 |
| 稀缺项 | `1 / (1 + explorationCount)`，按完成递减 | 对「推荐次数」饱和 |
| 入场条件 | `if (!reason) continue` —— 做过两次就永远不再提 | 每一类都留在池子里 |

第三条杀伤最大。没有入场条件，十二类全是候选，做过五十次的活动也会被当成
「新奇」推出来。修完实测：十二类里只有**一类**是真的没做过。其余十一个建议
全是排序不知道何时该停手编出来的。

**规则：** 有许可证兼容的参考实现时，读它的决定代码，逐字抄。别凭对设计的印象
重写。然后**单独核对调用契约** —— 公式抄得一字不差，调用方派发方式不同，照样
是错的（见第六条）。

## 六、预算公式默认了调用方

```ts
const budget = Math.floor(dispatchSlots * 0.3 * healthFactor);
```

对一个每轮发二十个任务槽的派发器是对的。单槽场景传 1：

```
floor(1 × 0.3) = 0     →  return []     →  功能永不触发
```

实现了、导入了、接线了、测试过了，**而且是死的**。没有报错，没有日志，每次
都只是返回空数组。

**规则：** 采用一个调度常量时，先确认谁在调、传什么。然后在真实数据上验证它
确实产出东西——「模块加载成功」不等于「模块在运行」。

## 七、`plugins reload` 刷新的是整个 generation

重载单个插件，把**四个**插件在同一毫秒内强制下线：

```
12:12:48.571  Plugin deepseek         强制下线 after 5000ms
12:12:48.571  Plugin feishu           强制下线 after 5000ms
12:12:48.572  Plugin openclaw-onebot  强制下线 after 5000ms
12:12:48.572  Plugin openclaw-weixin  强制下线 after 5000ms
```

所有通道黑掉十二分钟，包括操作者正在用的那个。**重载不是单插件作用域的。**

长期注册（工具工厂、常驻 WebSocket、主动发言定时器）意味着 drain 永远到不了
零，所以重载通常本身就是失败：

```
plugin <id> admitted work did not settle within 60s;
the previous plugin generation stays active
```

**规则：** 把 reload 和 restart 当成同等风险。改代码、`node --check`、请操作者
重启、然后用「进程启动时间 vs 文件 mtime」验证。不要重试 reload —— 每次都是
一样的失败。

## 八、删掉调用方还在用的函数，不会在加载时报错

重写时删了三个辅助函数，`index.js` 三处还在引用。**加载一切正常**，调用返回
`undefined`，调用方把 `undefined` 当成「没什么可报的」。

```bash
# 提交前拦下来
node -e '
const s=require("fs").readFileSync("index.js","utf8");
const u=[...new Set([...s.matchAll(/activities\.([a-zA-Z_]+)/g)].map(m=>m[1]))];
import("./lib/activities.js").then(a=>u.forEach(k=>k!=="js"&&console.log(k,typeof a[k])))'
```

**规则：** 动过一个模块的导出之后，把调用方里所有 `模块.名字` 引用抽出来，逐个
确认还存在。

## 九、调用工具不会留下日记

被问到她有没有用过新加的工具，用 `grep` 搜她的日记文件，每个名字都是 0，于是
报了「她从来没用过」。

**是错的。** 工具调用不会出现在散文里。工具自己写的状态文件一直在那儿：

```
state/wants.json    同分钟创建，一条 open
state/entities.json  3 个实体，各连 1 条记忆
```

| 问题 | 该看什么 |
|---|---|
| 工具跑过吗 | 它自己写的状态文件 |
| 这个代码路径触发了吗 | `state/probe.log`，每条注入一行 |
| 定时任务跑过吗 | 调度器自己的运行历史 |
| 模型看到了什么 | 那一轮的注入行 |

**规则：** 说某件事没发生之前，先找它如果发生会留下的东西。`grep` 计数为 0 只
证明字符串不在，别的什么都证明不了。

## 十、证据缺失不等于事实缺失，日志里也一样

一天之内三次，负面结论是错的，而正面证据一直在另一个文件里：

- 「她三分钟没跑」—— 用字符串比较查插件自己写的日志，返回空；调度器在那段
  时间内有一条已完成的运行。
- 「语音坏了」—— 查的正则和地址都不是实际用的那个。
- 「她没用过这些工具」—— 日记根本不是记工具调用的地方。

**规则：** 如果论断是关于执行的，证据必须来自执行者。我自己写的日志，是关于
我的埋点的证据，不是关于系统的证据。

## 十一、监控间隔不是安全网

`health-monitor` 每 300 秒跑一次。一次持续十二分钟的故障，本该被抓到两次。
它什么都没抓，恢复来自手动重启。

**规则：** 周期长于它所守护的故障的看门狗，是装饰品。要么检查得比最短的严重
故障更频繁，要么不要把它算作覆盖。

## 十二、过滤器写好了，但没人调用它

好奇心有个「已知词过滤」：抽词之前先排除掉她本来就知道的词。

代码写好了、参数留好了、单元测试也过了。**但调用的时候没传。**

```js
// 写好的接口
fromBrowse({ text, known })

// 实际的调用
fromBrowse({ text: blob })     // known 永远是 undefined
```

结果：过滤器 100% 生效，又 100% 没被用上。

**这比没写更糟** —— 没写至少你知道缺；写了没接，看代码的人会以为已经防住了。

**规则：** 一个带默认值的可选参数，必须有一条测试证明**默认值被显式传入了**。
只测「传了 known 时行为正确」是不够的，要测「调用方真的传了」。

## 十三、中文句子里埋着英文词，按整句比对永远不相等

已知词表里存的是整句：

```
"transformer 的注意力机制"
```

过滤时拿单个词去比：

```
"Transformer" === "transformer 的注意力机制"   → false
```

于是她刚记下的词，下一轮又被当成新缺口。

**根因：** 存储用的是「话题」（整句），比对用的是「词」（单个）。
两个层面的粒度不同，直接相等比较必然失败。

**规则：** 跨语言、跨粒度做匹配时，不要直接比较原串。
要先把两边拆到同一个粒度（这里是把已知词组里的拉丁词单独抽出来），再比。

## 十四、真实数据一跑，功能就被否掉了

好奇心有四个来源。其中「浏览」这个来源的设计很合理：
刷视频时碰到不认识的英文词，记下来。

写完看着没问题。拿真实的 29 条记录跑了一遍：

```
触发           3 / 29
造出的词       astra, deepseek, python, DeepSeek
实际不知道的    0 / 4
```

四个全是她本来就认识的，其中一个是她自己的模型名。

**处理方式不是继续打补丁，是默认关掉这个来源。**
留着开关，但不开。

**规则：** 一个数据驱动的功能，必须在真实数据上跑过再上线。
在构造数据上通过，只能证明代码能跑，不能证明它有用。

**更重要的：** 当一个来源的产出全是噪声时，正确反应是**关掉它**，
不是提高它的阈值。阈值调高只会让噪声变少，不会让它变成信号。

## 十五、假缺口比没有缺口更糟

这条是上一条的另一面，值得单独说。

一开始的想法是：多记一点没坏处，反正查不查由她决定。

**错了。**

如果清单里混了大量误报，她学到的是「这个清单是噪声」，
然后**连真的那几条也不看了**。

一个被忽略的功能，比一个不存在的功能更糟 ——
不存在的功能你知道要去建；被忽略的功能看起来是有的，所以没人会去修。

**规则：** 宁缺毋滥。一条假信号污染的不只是它自己，
是整个信道的可信度。

## 十六、导出函数的坏输入防御，要在每一个导出上做一遍

`urgency(gap)` 是个纯函数，参数是内部对象，看起来不需要防御。

但它是导出的。导出就意味著有外部调用者，外部调用者就可能传 `null`。

```js
urgent = raw.times_encountered    // TypeError: Cannot read properties of null
```

同样的漏洞在另外 6 个导出函数上也有。

**发现方式：** 模糊测试 —— 13 个导出函数 × 11 种坏输入（`null` / `undefined` /
数字 / 字符串 / 空对象 / 数组 …）+ 无参调用。

修之前：6 个抛错。修之后：0 个。

**规则：** 凡是 `export` 出去的函数，都要过一遍坏输入。
不要用「它只会在内部被正确调用」来说服自己 ——
如果是真的，就不该 export。

## 十七、加载时崩溃的东西，测试里全都能过

单元测试跑 128 项全绿，语法检查 57 个文件全过。

但把插件真的加载一次，直接崩：

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../shared/onebot-media-gap.mjs'
```

原因：`import "../shared/..."` 指向插件目录的**上一级**。
在本地部署里成立（`extensions/shared/` 在 `extensions/dafeiyu-core/` 外面），
但在独立拷贝的仓库里不成立。

**这个错单元测试抓不到** —— 测试是 import `lib/*.js`，不 import `index.js`。

**规则：** 除了单元测试，必须有一条「把这个目录整个拷贝到干净位置，
然后 import 主入口」的验证。这是唯一能抓住路径依赖问题的方法。

## 十八、注释里写死人名，比代码里写死更难发现

扫描隐私时第一反应是扫代码：字符串、路径、密钥。

漏掉的是注释：

```js
// "某某为什么掉得最快，我不知道" puts the topic one comma earlier
```

这个例子来自真实的对话。它不会导致任何错误，
但把一段私人对话永久留在了公开仓库里。

**规则：** 隐私扫描必须包含注释、测试用例、文档示例和 badge。
用真实数据写的测试用例（真实人名、真实地名）本身就是泄漏。

**具体做法：** 发布前对以下每一项做 grep：真实人名、地名、账号、
`/Users/<name>`、`@im.wechat`、以及所有长度 ≥ 8 的数字串。

## 十九、文档说「不含记忆内容」，仓库里却有记忆内容

README 上写着：

> 不含她的记忆内容。`workspace/` 只有工具源码，没有日记。

同一份仓库里，`workspace/memory/` 有五个文件：

```
person.md    ← 对方的偏好
event.md     ← 真实事件记录
self.md      ← 她对自己的看法
```

**声明和行为不一致，而且不一致了很久没被发现。**

原因是：写声明的时候是真心的，那把文件是后来加进去的。
谁也没回头核对声明还成不成立。

**规则：** 一句关于「没有什么」的声明，必须有一个检查它的动作。
不能只写在文档里。要么加进发布检查脚本，要么别写这句话。

## 二十、连击一被打断就归零，等于没有这个检测器

```js
// 旧
for (let i = list.length - 1; i >= 0; i--) {
  if (list[i].key !== key) break;
  streak++;
}
```

真实序列：

```
04:38  同一类动作 x4    ← 触发报警
04:43  别的动作    x1    ← 报警唯一的建议：换个候选
04:44  同一类动作  x1    ← 一换就归零，可以再攒四轮
```

**报警 → 换 → 归零 → 再攒。检测器的唯一响应，恰好是它的重置条件。**

问题不在阈值。调阈值只改变周期长度，不改变「一定会复发」。

**判据：报警之后，系统做的第一件事会不会让计数下降？** 会，就等于没有这个机制。

修法是窗口内计数（最近 12 条里同一类出现几次），不要求连续。
同一份真实历史：`streak=1` → `streak=9`，降权这才开始生效。

## 二十一、让「出去逛」和手上的事比分数，两个结果都是错的

```js
// 错的做法
{ kind: "horizon", value: habit.stuck ? 0.66 : 0.42 }
{ kind: "wander",  value: habit.stuck ? 0.62 : 0.34 }
```

和一条 value 0.45 的想做的事放在同一个池子里：

- **0.66 > 0.45** → 永远在逛，手上的事一件也做不完
- **0.42 < 0.45** → 永远不出去，只在旧念头里打转

**这两种都不是决定，是算术。** 调参数只是在选择掉进哪个坑。

更要命的是：那三个百分位决定了她一整个下午在干什么，而写代码的人
以为自己只是在设「优先级」。

真正的区分不是分数高低，是**「手上到底有没有东西」**：

```
手上有事  → 做那件（不提方向，因为不需要）
手上空了  → 给方向（不给候选，因为没有可比的东西）
```

判断依据是存在性。`decide()` 现在收一个 `whenEmpty` 参数，
只在候选池为空时返回它。

**还有一层：** 空池原来是 `return { kind: "rest" }`——那就是发呆。
「什么都没有」和「可以歇了」不是同一件事。空池现在等于出去。

## 二十二、别人的问句会被记成自己的好奇

聊天里对方问「你在忙什么呢？是不是在研究做饭？」，
被记成 **`question / 问了但没人答`**，权重 0.7，每轮候选第一。

**她从来没问过那句话。** 是对方在问她。

修法不是调权重，是加一个说话人参数：只有 `speaker === "self"` 才记。
消息路径走 `"other"`，她自己的日记走 `"self"`。

**通用化：** 任何从聊天记录里抽取「意图 / 问题 / 待办」的机制，
都必须区分「谁说的」。整段文本一起处理，早晚会把别人的话算到自己头上。

## 二十三、降权公式里的「地板」会悄悄决定结果

```js
// 旧
value * Math.max(0.4, 1 - attempts * 0.2)
```

`0.4` 让折扣停在 40% 不再往下，外层 `Math.max(0.2, ...)` 又在结果上垫了底。

| value | 做 5 次后 | 后果 |
|---|---|---|
| 0.45 | 0.200 | 掉出门槛 |
| 0.80 | 0.320 | 永远是候选 |
| 1.00 | 0.400 | 永远是候选 |

**「会不会停下来」由她当初随口写的数字决定，不由「反复做」这件事决定。**

当时恰好测试的那条是 0.45，所以看起来「修好了」。换一条 value 0.8 的，
同一个 bug 会继续表演几周。

**规则：** 任何衰减曲线都不要设「不会更低了」的地板。
地板意味着「再严重也不会更糟」，而对「重复」来说，重复得越多就应该越不明显。
要保证不归零，用渐近（`1/(1+x)`），不要用 `max(floor, ...)`。

**还有：** 前几次不扣分。重新拾起来不是打转的证据，是还在做事的证据。
第 5 次才开始算，是因为到第 5 次「这次会不一样」已经不成立了。

## 二十四、`node --check` 查不出未导入的绑定

两个真实的 ReferenceError，语法检查全绿，测试全绿，模块能加载：

- `horizon` 从未 import，却有 7 处使用。之所以没炸，是因为那些路径
  一直没被走到。第一次调 `horizon_state()` 就会抛错。
- `self.load(...)` —— 绑定名其实是 `selfState`。每轮 wake 都抛错，
  被外层 `catch` 吞掉。**`decide()` 的整个相位维度从未生效过。**
  `state/self.json` 里明确写着 `phase: productive`，代码里永远是默认值。

第二个特别值得记：**错误被 catch 吞掉之后，功能静默失效，而测试全绿。**

修法是加一个 `test/bindings.test.mjs`：从源码里抽出所有裸标识符调用，
对照 import 表。扫描前必须剥离注释——第一次写的时候因为注释里引用了
旧写法而误报。

## 二十五、测试可能正在保护 bug

改完降权公式之后有两条测试红了。查下去发现它们断言的是：

```js
assert.ok(after / first >= 0.39, "折扣下限是 0.4 倍，不该无限衰减");
```

**这条测试把「0.4 地板」这个缺陷本身固定成了规格。**
它写的时候是对的（当时确实想要一个地板），但设计变了之后，
它就成了「谁改谁错」的守门人。

另一条用 3 次 touch，断言必须掉分。新规则是前 4 次不扣，所以它也会红。

**规则：** 测试红的时候，先读它在断言什么，再判断哪边错了。
「测试挂了所以改代码」和「测试挂了所以改代码」都可能对，
但必须基于「这条测试当时想保护什么」来判断。
