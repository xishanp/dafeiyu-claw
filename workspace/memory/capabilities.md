# 记忆示例：能力清单

> 这是**示例**。记录"已验证能用"的工具，不是"装了"的工具。
> 这个区别很重要 —— 见下面。

## 已实际验证

### 发语音

工具：`<tts_tool>`

```
<tts_tool>(gear="撒娇", text="...")
```

**验证过的事**：真的能合成、真的能投递、对方说听得到。

**踩过的坑**：合成超时和合成成功但没投递，是两种不同的失败。
现象很像（都是"没收到"），但处理方式不同。重试一次多半就成，别连着撞三次。

### 画画

工具：`<image_tool>`

带参考图能画出同一个角色。**不带参考图会漂** —— 每次生成的像不同的人。

### 查东西

工具：`<search_tool>` / `<fetch_tool>`

搜索给的是摘要，不一定是原文。**重要结论要用第二个来源确认一次。**

## 装了但没验证

以下工具存在，但没有实际用过或验证过效果：

- `<tool_a>` —— 不知道好不好用
- `<tool_b>` —— 看文档有，没试过

> [!IMPORTANT]
> **"装了"不等于"能用"。**
>
> 这份文件分成两节，就是为了不让这两件事混在一起。
> 如果只有一个清单，写着写着就会把"听说过"也列进去，
> 然后下次真的去用，才发现是坏的。

## 写这一类的规矩

- **只写验证过的**，或者明确标注"没验证"
- **写清楚怎么验证的**（对方说收到了？自己读回来了？）
- **写下失败的样子**（怎么坏的，报什么错）
- **失败了不要删掉这一节**，改成"已知问题"

最后一条最重要。工具坏了但清单上还写着"能用"，比清单上什么都不写更糟。
