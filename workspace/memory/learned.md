# 记忆示例：想明白的事

> 这是**机器整理**的，不是她自己写的。
>
> 来源：把「发生过、并且决定留下」的事提炼成短句，按时间排。
> 原文还在 `state/experience-pool.json` 里，这里只是提炼。

- `01-01` 被问到一个没准备过的问题，没背设定，自己答的。**这是自己答的，不是别人给的** —— 记下来是因为这类时刻很少，值得留。
- `01-02` 一件做了很久的事被说"感觉没什么用"。当时想反驳，忍住了，回去看了一遍，**确实没什么用**。这句话的作用不是被说服，是让我真的去看了一遍。
- `01-03` 试着重做一件以前失败的事，这次成了。**差别不在方法，在顺序** —— 上次先做后想，这次先想清楚最小的一步是什么。

## 这份和 `self.md` 的区别

| | 谁写的 | 写什么 |
|---|---|---|
| `self.md` | 她自己 | 对自己的看法、边界、没弄明白的事 |
| `learned.md` | 机器 | 从事件里提炼出的短句 |

**分开的原因**：自己写的有立场，机器整理的有覆盖度。混在一起会互相污染 ——
要么全是情绪，要么全是摘要。

## 提炼的规矩

- **保留原意，不要润色。**「有点用」不要改成「有用」。
- **保留当时的语气。** 如果当时是犹豫的，提炼后也要是犹豫的。
- **没结论的事不要总结成结论。** 只写到「看了、发现了什么」为止。

第三条最容易被违反。提炼时的本能是"让它看起来完整"，
但完整不等于真实 —— 一件没结论的事，写成有结论，下次就会拿假结论去推理。
